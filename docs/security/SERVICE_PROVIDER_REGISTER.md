# CAT Service Provider Register

No credentials, tokens, account IDs, tenant IDs, private URLs, or named administrator identities belong in this file. Review at least annually and before onboarding/offboarding a provider.

| Provider/service | Purpose and CAT data | Security responsibility / admin access | Dependency risk | Offboarding and data handling |
| --- | --- | --- | --- | --- |
| GitHub | Source, history, issues/PR metadata, CI logs/artifacts, encrypted secrets | GitHub secures platform; CAT controls collaborators, branches, Actions, secrets, alerts; individual MFA admins | Source/pipeline compromise or outage | Export repo/security evidence; revoke tokens/apps/runners; retain required history; delete secrets/artifacts per policy |
| Vercel | Production/preview builds, request/runtime logs, environment secrets, transient protected processing | Vercel secures hosting; CAT controls project access, environments, domains, firewall, drains and deployment protection | Runtime/deployment compromise or lock-in | Export env/config securely, redeploy elsewhere, revoke integration, remove domain/project/data after validation |
| Neon | CAT PostgreSQL data, protected PII envelopes/indexes, audit records, backups/history | Neon secures managed database; CAT controls project access, credentials, branches, TLS, backup/restore | Data unavailability/loss, privileged access, plan retention | Logical dump/restore to replacement; revoke credentials; delete branches/project after verified migration and retention decision |
| Cloudflare R2 | Encrypted application objects and separate recovery archives | Cloudflare secures storage; CAT controls private access, tokens, buckets, lifecycle/locks | Object loss, misconfiguration/public exposure | Inventory/copy ciphertext and checksums, revoke tokens/domains, delete only after verified recovery/migration |
| Microsoft Entra ID | OIDC identity, verified email, MFA claims, authentication/admin events | Microsoft secures identity service; organization controls lifecycle, MFA, admins and recovery; CAT revalidates local access | Authentication outage/compromise | Export identity/admin records where permitted, configure replacement OIDC, revoke old client secret, unlink only under approved migration |
| Shared `scan.cyang.io` malware scanner | Bounded uploaded file bytes and verdict metadata; designed for no retention | Scanner operator secures scanner; CAT uses per-app HMAC, allowlisted endpoint and fail-closed handling | Upload outage or missed malware | Disable credential, replace scanner after acceptance tests, confirm no retained CAT content |
| DNS/Cloudflare zone | `cat.cyang.io` routing and TLS-related control | Domain administrators control records and access | Domain hijack/outage | Transfer/replace DNS only through approved change with rollback evidence |
| Sentry | Redacted CAT Production application errors and alert metadata | Sentry secures the service; CAT controls aggressive filtering, project access, alerting and retention | Sensitive log exposure or missed alerts | Export required incident evidence, revoke CAT DSN/access, and delete retained events per approved policy |

Contract/security review must cover confidentiality, incident notice, subprocessors, deletion/return, availability/recovery, administrator access and transfer/termination. Legal/privacy counsel determines required contractual terms; repository documentation does not approve them.
