# CAT Security Responsibilities Guide

## Everyone

- Use only your own approved account; never share accounts, MFA codes, sessions, download links, or credentials.
- Use the organization-approved device/browser/network. Lock the device when unattended and log out of shared devices.
- Do not upload or enter real member data into Preview, tests, screenshots, tickets, chat, source code, or unrestricted narrative fields.
- Minimize downloads and exports. Protect approved files outside CAT and delete them when the approved purpose/retention ends.
- Follow document visibility labels. Do not forward restricted documents or copy data to personal email/storage.
- Report suspected unauthorized access, a lost device, unexpected MFA prompt, malicious file, mistaken export, or credential exposure immediately through the organization-designated private channel.

## CAT members and leads

- Access only assigned or role-authorized member information and use it only for approved CAT work.
- Put sensitive narrative content only in the protected note workflow and choose the narrowest appropriate visibility.
- Leads must not broaden access or exports to simplify coordination; request the correct role/assignment change.

## Administrators

- Apply least privilege, provision individual accounts, review access quarterly, and deactivate leavers/dormant accounts promptly.
- Confirm high-impact import/campaign actions against current state; never bypass stale-state, approval or explicit assignment controls.
- Review security/audit events and provider alerts, protect recovery keys/credentials, and record provider configuration evidence.
- Do not enable production launch flags until every production security gate item has evidence and explicit approval.
